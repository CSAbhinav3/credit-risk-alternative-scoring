# Alternative Credit Scoring for India's Underbanked Population

A fairness-audited, explainable credit-risk scoring pipeline built for a final-year
B.Tech CSE research project (Christ University, Bengaluru). Combines real bureau data
(Home Credit Default Risk) with synthetic UPI-style behavioural data calibrated to RBI
DPSS statistics, then evaluates the resulting XGBoost model jointly on **performance**,
**explainability** (SHAP), and **fairness** (Fairlearn / AIF360) — three axes a recent
systematic review (Bahlool et al., 2026, *JRFM*) found are rarely studied together.

## Results at a glance

| | |
|---|---|
| Model | Tuned XGBoost (bureau features) |
| AUC / Gini / KS | 0.7913 / 0.5825 / 0.4404 |
| Fairness attributes audited | Gender, region tier, education, occupation (AIF360 `EqOddsPostprocessing` mitigation on each) |
| Decision threshold | Cost-calibrated at **t\* = 0.71** (example-dependent cost-sensitive framework, Bahnsen et al. 2014) — 22.2% lower expected cost than an arbitrary 0.5 |

Do synthetic UPI features add predictive value over bureau data alone? **No** — ablation
shows UPI-only AUC of 0.5023 (chance level), traced to the generator's only real-data
anchor (`AMT_INCOME_TOTAL`) itself barely correlating with default. Reported as a
diagnosed, honest negative result, not smoothed over — see `CLAUDE.md` for the full
derivation and every other finding (including where results *didn't* meet the original
targets).

## Setup

```bash
git clone https://github.com/CSAbhinav3/credit-risk-alternative-scoring.git
cd credit-risk-alternative-scoring
python -m venv venv
venv\Scripts\activate          # Windows; use `source venv/bin/activate` on Linux/Mac
pip install -r requirements.txt
```

**Data**: download the [Home Credit Default Risk](https://www.kaggle.com/competitions/home-credit-default-risk)
competition's CSVs from Kaggle and place them under `data/raw/home-credit-default-risk/`
(gitignored — not included in this repo).

## Reproducing the pipeline

Run the notebooks in order with a full **Restart Kernel → Run All Cells** each time
(never run cells in isolation — see `CLAUDE.md` for why that matters here):

1. `01_eda.ipynb` — exploratory analysis
2. `02_feature_engineering.ipynb` and `03_synthetic_upi.ipynb` — feature pipeline + synthetic UPI data (Track A + Track B), producing `data/processed/train_fe.parquet`
3. `03_modelling.ipynb` — baselines, ablation, Optuna tuning, stacking; produces `models/tuned_xgb_bureau.joblib`
4. `04_shap_explainability.ipynb` — global/individual SHAP, saves figures to `figures/`
5. `05_fairness_audit.ipynb` — fairness audit, AIF360 mitigation, cost-calibrated threshold

Then export the dashboard's fairness data and launch it:

```bash
python src/export_fairness_results.py   # writes reports/fairness_results.json
streamlit run dashboard/Home.py
```
